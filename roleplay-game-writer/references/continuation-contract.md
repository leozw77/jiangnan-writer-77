# 角色扮演续写契约

## 作者主导的输出顺序

1. **路线选项**：在动笔前给出几条方向不同、后果不同的路线。
2. **用户梗概**：等待用户选择路线并补充本轮实际想发生的内容。
3. **场景续写**：把用户梗概写成完整文学化场景，只对环境、动作、过渡和非关键反应进行补写。
4. **下一轮选项**：正文之后给出固定选项，同时保留用户自定义行动入口。
5. **save_state**：按 `game-state-schema.md` 区分确认事实和模型提案。
6. **确认栏**：列出本轮模型新增的关键提案；用户未提出异议而直接继续时默认确认，用户提出修改时撤销冲突提案及其依赖项。

## 权限规则

- 玩家角色的意图、决定、内心结论和关键动作必须由玩家提供，除非用户明确授权代演。
- NPC 可以根据各自的目标、知识和误解主动行动，但不能使用角色不可能知道的信息。
- 不把选项列表当成唯一行动；允许玩家自由输入其他行动。
- 失败、沉默、拒绝和不行动也是合法结果，不强行把场景推向预设剧情。
- 路线选项只是规划工具；未被用户选择的路线不是世界事实。
- 用户只给出粗略事件时，模型可以文学化补足，但改变人物关系、身份、死亡、能力、重大秘密或主线方向的内容必须标为提案。

## 连续性规则

- 先加载当前状态，再写新场景；不要只凭原始长档案凭印象续写。
- 新信息必须标记为已确认、角色推测或待确认，不能把推测写成世界事实。
- 每轮至少让任务、关系、信息、资源或代价中的一项发生可追踪变化。
- 导出、总结、修订、技能制作等元对话默认不进入世界时间线。
- 用户没有明确确认但继续推进时，上一轮提案转为确认；仅讨论元问题时不触发默认确认。
- 用户后续修改优先于旧模型提案；当前记忆撤销冲突项和依赖项。原始导出可按项目要求清理 Skill/导出等元讨论，但剧情正文与用户纠正必须保留。
