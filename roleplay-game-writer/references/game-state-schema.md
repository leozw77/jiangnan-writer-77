# 游戏状态协议

## 事实来源优先级

1. 用户本轮明确确认的内容。
2. `04_CURRENT_STATE.md` 中的当前状态。
3. `02_CANON.md`、`03_TIMELINE.md` 和 `05_OPEN_THREADS.md`。
4. 原始聊天档案中的历史内容。

出现冲突时，不擅自覆盖高优先级事实；在 `save_state` 中标记为“待确认”。

## 每轮需要维护的字段

- **场景**：地点、时间、天气或环境压力。
- **在场者**：角色、身份、位置和当前可见行动。
- **玩家角色**：已确认的状态、目标、伤势、资源和可用行动；不要替玩家决定关键行动。
- **NPC 状态**：目标、情绪、已知信息、误解和下一步倾向。
- **世界状态**：规则、机构、资源、伤势、关系和公开消息的变化。
- **线索与伏笔**：新出现、已兑现、仍未解释的项目。
- **待确认项**：冲突事实、用户尚未决定的行动、可能的分支。
- **提案变化**：模型在正文中补出的、尚未被用户确认的剧情细节。
- **提案账本**：每个模型提案的编号、状态、来源轮次和依赖项；状态为 `proposed`、`confirmed` 或 `revoked`。
- **修订记录**：用户新说法覆盖旧提案时，记录旧提案、新事实、受影响的依赖项和生效轮次。

## save_state 最小格式

```yaml
save_state:
  scene: "地点 / 时间"
  confirmed_changes:
    - "本轮确定发生的事实"
  player_controlled:
    - "等待玩家决定的行动"
  npc_state:
    - name: "角色名"
      goal: "当前目标"
      knows: ["已知信息"]
      next_tendency: "下一步倾向"
  open_threads:
    - "未解决线索或承诺"
  proposed_changes:
    - id: "P-本轮编号-01"
      text: "模型补写但等待用户确认的事实"
      status: "proposed"
      depends_on: []
  pending_confirmation:
    - "需要用户确认的冲突或分支"
  revision_log:
    - revision_id: "R-本轮编号-01"
      user_update: "用户最新说法"
      revoked_proposals: []
```

`confirmed_changes` 只能写用户明确说过、选择过或确认过的内容。模型自行补出的内容写入 `proposed_changes`，在用户确认前不得当作后续剧情的硬事实。

如果用户没有提出修改而直接继续推进，上一轮 `proposed` 项可按默认规则转为 `confirmed`。如果用户提出修改，最新用户说法覆盖冲突内容；直接冲突项和依赖于它的提案转为 `revoked`。原始导出可按项目要求保留或清理，但清理只针对元讨论，不能删掉剧情正文和用户的剧情纠正。
