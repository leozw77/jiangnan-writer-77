# 来源、净化和回溯规则

## 当前目录

- `source/raw-chat-export.json`：从分享聊天导出的结构化原始源，203 个回合、包含 1584 条线性消息范围；用于精确回溯，不直接作为续写记忆。
- `source/raw-chat-export.md`：完整文本导出副本，包含剧情和后期元讨论。
- `source/plot-only-transcript.md`：去除 Skill、导出、安装、审计、工具和明显项目管理元讨论的剧情证据层；保留用户剧情纠正。
- `source/export-stats.json`：导出统计，记录 203 个回合、239 条助手文本消息、约 56 万导出字符等原始信息。
- `source/world-setting-original.txt`：从用户最初 DOCX 提取的世界沙盘设定；它是 `source-only` 参考，不能覆盖用户后来明确改过的游戏事实。
- `episodes/`：从净化剧情档案按阶段切分的详细回合副本。
- `../roleplay-game-writer/`：Skill 和文学化表达参考，不是剧情档案。

## 净化边界

- 直到回合 125 的剧情、用户选择、用户纠正和场景正文属于剧情证据。
- 回合 90-93 是 Skill 加载/测试，排除；回合 126 以后主要是 Skill、导出、GitHub、记忆、压缩包和工具讨论，全部排除。
- 任何文件中出现的 Skill、GitHub、导出、安装、Token、脚本、压缩包或模型运行说明，除非用户明确把它写进角色世界，否则不能进入剧情 Canon。

## 冲突处理

1. 用户本轮最新明确修改。
2. `06_PROPOSAL_LEDGER.md` 中的已确认/撤销链。
3. 事件账本和人物状态。
4. 用户原始 DOCX 中的世界参考。
5. 原著参考逻辑。
6. 模型自己的补写。

如果冲突不能由这些规则解决，标 `conflict` 并停下来询问，不擅自合并两个版本。

## 回溯规则

- 需要核对细节时先读相应 `episodes/` 分段，再读 `source/plot-only-transcript.md` 的原始回合。
- 不用完整原始导出推断当前状态，不把模型第一轮复述中的一句话当作比用户后续修正更高的事实。
- 记忆文件没有记录的细节，不允许模型用“原著大概如此”伪装成已经发生。
