# 续写连续性检查清单

## 写作前

- [ ] 已读取 `00_INDEX.md` 和当前场景对应的记忆文件。
- [ ] 已确认当前地点、时间、在场人物和上一个场景的结尾动作。
- [ ] 已核对主要人物的身体状态、持有物品、目标和即时威胁。
- [ ] 已核对信息差：谁知道秘密，谁只能猜测，谁明确不知道。
- [ ] 已检查 `06_PROPOSAL_LEDGER.md`，没有误用 `revoked` 内容。
- [ ] 已检查 `09_FORESHADOWING.md`，没有遗漏会影响本场景的伏笔。
- [ ] 已确认用户本轮对 77 的行动授权；模型不替 77 做关键决定。
- [ ] 已区分现实层与精神/幻境层；路鸣泽的具象化动作不自动等于实体在场。
- [ ] 若路鸣泽或小魔鬼出现，已标明 channel（mental_scene、mental_voice、sms 或明确的 host_possession）及可见/可听对象。
- [ ] 奶妈/保姆三人组若听到路鸣泽，只能按心声、精神传达或通讯处理；没有把“听见”误写成“看见”。
- [ ] 若要改变原著外部节点，已得到用户明确选择或修改。

## 成文时

- [ ] 场景有具体任务、关系压力和可见变化。
- [ ] NPC按照各自目标和已知信息行动，不因为记忆文件而全知。
- [ ] 新能力有来源、限制、代价和可观察后果。
- [ ] 新增重大事实先视为 `proposed`，不在正文中伪装成旧 Canon。
- [ ] 文风服务于场景，不用风格模仿覆盖用户确定的剧情。

## 交付后

- [ ] 输出完整正文，而不是只输出提纲。
- [ ] 输出 3-6 条明确不同的下一步路线。
- [ ] 输出确认提示：用户明确修改时，删除旧事实及依赖；继续推进则默认确认。
- [ ] 输出 `save_state` JSON，标明 `turn_id`、`kind`、`status`、`items`、`depends_on`。
- [ ] 增加一条剧情回合计数；元讨论不计数。
- [ ] 检查是否达到 5 回合同步门槛或触发强制同步条件。
- [ ] 未启用 GitHub 时，只报告“待同步”，不声称已写入远端。
